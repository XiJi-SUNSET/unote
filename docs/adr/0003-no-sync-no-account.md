# ADR-0003：不做账号、不做同步

- **状态**：Accepted
- **日期**：2026-10-17
- **决策者**：项目作者
- **关联**：[01-tech-stack.md](../01-tech-stack.md) · [06-prior-art.md](../06-prior-art.md)

## 背景

几乎所有笔记应用在某个阶段都会加上账号与同步。同类项目的调研结果（见 [06-prior-art.md](../06-prior-art.md)）显示：一旦加上同步，架构复杂度会跳一个数量级——

- `catch` 演化成 Docker + 服务端 + monorepo
- `crossnote` 演化成浏览器内 git + workspace + patches

而 Unote 的核心承诺是"5 秒内接住一个念头"和"数据只属于你"。

## 决策

**不做账号，不做同步，不做多端漫游。**

数据迁移只通过一种方式：导出 ZIP → 手动导入另一台设备。

## 理由

1. **同步会改变产品的每一个角落**：冲突合并、离线队列、鉴权、服务端运维、隐私政策。这些成本最终都由"打开就能写"来偿还。
2. **同步会破坏"无网"这条最硬的承诺**。一个没有 `INTERNET` 权限的 APK，是可以在"应用信息 → 权限"里给用户看的证据。加了同步，证据就没了。
3. **迁移需求是低频的**。一个学生换手机的频率约 2–3 年一次。为两年一次的需求，把每天都要用的启动路径拖慢，不划算。
4. **ZIP 比同步更长寿**。服务端会关停、API 会改版，一个装满 `.md` 和 `.webp` 的压缩包二十年后还能打开。

## 后果

**正面**

- 启动路径上没有网络等待、没有鉴权、没有状态同步
- 隐私故事极简：没有服务器，就没有泄露
- 可以给出可验证的承诺（清单无 `INTERNET` 权限）

**负面**

- 多设备用户需要手动搬运
- 手机丢失 = 数据丢失（除非有导出习惯）→ 靠 [03 §6](../03-data-backup.md) 的安全网缓解，但缓解不等于解决
- 无法做"分享一篇笔记给同学"这类功能

**需要持续观察**

- 如果用户反复抱怨"换手机太麻烦"，优先做"局域网直传（无服务器、无账号）"，而不是加云同步。局域网直传仍然不需要 `INTERNET` 权限之外的任何东西，可以作为 v2 的候选。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 云同步 + 账号 | 违反产品定位；运维与隐私成本不可控 |
| WebDAV / 自建同步 | 仍需网络权限与凭证管理，且对目标用户（大学生）门槛过高 |
| 局域网直传 | 不是否决，是**延后**；v2 可考虑 |
| 导出/导入 ZIP | **采纳**，即本 ADR 的唯一迁移路径 |

## 缓解措施

- 每日本地快照（保留 7 份）
- 导出提醒（首次使用第 7 天、此后每 30 天）
- 设置页常驻"上次备份：N 天前"
